# 反向 grill-me 拷问问题清单

当解析中出现含糊（"可能""大概""通常""应该是"）时，逐条套用下面的问题拷问自己。每个问题必须落到：已证实（附来源）/ 合理推断（标注推断）/ 未公开（说明验证路径）。

## 身份与版本
- 我解析的到底是哪个版本？参数规模是哪个档位？论文、官方博客、HF 模型卡三处的数字一致吗？
- 这个名字是否有同名不同架构的模型（如 Llama 2 vs 3 的 GQA 差异）？

## 每个硬数字
- 层数 / hidden size / 头数 / KV 头数 / 词表 / 上下文长度——来源是哪？论文原文还是二手博客？能否在官方 config.json 里复核？
- 总参数量与"层数 × 每层参数"能否粗略对账？对不上是哪里错了？
- MoE：专家总数、激活 top-k、有无共享专家、路由机制——官方说的是哪个？

## 每个机制判断
- 归一化是 RMSNorm 还是 LayerNorm？Pre-Norm 吗？我凭什么这么写——代码证据还是论文？
- 位置编码的 base 值、scaling 方案（YaRN/NTK/无）——长上下文版本是否改过？
- 注意力变体（MHA/GQA/MLA）——我是不是在把"同类模型常见做法"当成了该模型的事实？

## 五维完整性
- 每个节点五条（是什么/内容/做什么/目标/意义）是否齐全？哪条在用空话凑数？
- "意义"一条是否有对比（相比替代方案好/差在哪）？还是只在复述功能？

## 一致性
- 各节点维度能否串成一条完整数据流（嵌入维度 → 层内维度 → 输出维度）？
- 正文节点与流程图节点是否一一对应？

## 收尾
- 所有"未公开"项是否列成了清单，并写明已尝试的验证路径（查过什么、为什么查不到）？
